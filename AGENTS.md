# Project conventions

- Current research uses two parallel tracks from existing Motus multi-task SFT pi0.5 on RoboTwin. Method exploration studies a minimal critic and continued-SFT/value warm-up; prerequisite experiments establish P0 capability, fixed offline data, shared/independent critic controls and common-policy updates. Do not rebuild another base model. Follow `configs/multitask/two_track.json`, `configs/multitask/phase0.json` and `docs/multitask-critic.md`; the two-track JSON is a plan, not a training launcher.
- Source pins in `bootstrap/sources.lock.json`: RLinf `e1a82ebf0c1af69da6ab9b1519f5f3692fe33566` (`e1a82eb`), RoboTwin `dca9ec682688821c42944eacd7f5dd9bfb15396f` (`dca9ec6`). The two source snapshots are vendored using `third_party/sources.manifest.json` and an exact-file ignore allowlist. Verify against the manifest offline and against locked ZIP archives when cached, accepting only the recorded RLinf compatibility patch. Do not track downloaded assets/caches or the duplicate `RLinf-recap-official/` tree. Snapshots are not nested Git checkouts, so Git may report the parent project revision.
- Preserve the separate LIBERO public-workflow reproduction in `third_party/RLinf-recap-official/` and its locks, models and results. Its 1000-step self-SFT is a reference artifact, not the new Motus P0. Do not start its long critic/CFG budgets under the superseded priority. Its original reported 48.8%/66.5% initialization was not released; do not claim an exact reproduction.
- RoboTwin uses pinned `third_party/RLinf/` with the recorded compatibility patch. The original RECAP critic consumes images and instruction, not proprioception, and uses its own SigLIP/Gemma backbone. Adding q, elapsed time or frozen policy features are separate factors. Do not silently attribute those changes to contrastive supervision.
- Freeze offline training data before method comparisons; evaluation never returns to training. Require complete-episode and traceable scene splits, per-task outcome coverage, critic/value/advantage diagnostics, and common policy initialization/update rules. Goal-pair auxiliary supervision is ineligible without verified pairs; different task names are not automatic negatives. Ordinary shared-vs-independent comparisons or adding an auxiliary loss are not established novelty.
- Hardware roles chosen by the user: this 2x48GB RTX 4090 host is for method development and small controlled validation; the 8x48GB RTX 5880 host is for prerequisite evidence, frozen data preparation, trusted baselines and large experiments. Share pinned artifacts and protocols; promote locally screened methods to large controlled confirmation. Do not default to reserving this host only for evaluation or combining both hosts into one distributed job.
- Server task documents are `docs/method-2gpu.md` and `docs/prerequisite-8gpu.md`; shared scientific controls and handoffs stay in `docs/multitask-critic.md`. Keep README as navigation. Pilot configs live in `configs/robotwin_pilot/`, separate from current `configs/multitask/` and LIBERO `configs/recap_official/`; do not duplicate canonical model/source pins in the planning index.
- Joint SFT/value exploration is a separate method from original RECAP: use reliable success data for SFT, success/failure for value, match representation/input/capacity in stop-grad controls, and measure actual shared gradients. Report actor changes before RL and separate actor initialization from critic-label effects. M0 engineering may use explicitly tagged development data with known limitations; it does not waive formal dataset or final-test gates.
- Use the pinned official code in `third_party/`; project extensions belong in `src/vla_rl_mt/`, Hydra overrides in `configs/`, launch tools in `scripts/`, and preparation in `bootstrap/`.
- The user authorized condensing existing experiments into `docs/previous-experiments.md` and removing old records/figures/snapshots from the repository-facing tree. They were moved to ignored `.runtime/retired/`; do not restore old dashboards or archives. Keep literature/research ideas, reusable tools, source/model locks, models and datasets. New experiment artifacts stay in ignored runtime directories.
- Preserve running downloads/installers; do not launch two writers for the same resource directory.
- Keep models, datasets, credentials, environments and checkpoints out of Git. Preserve the source and model locks.
- Do not claim RoboTwin RECAP is runnable until LeRobot conversion, ALOHA transforms, and the official four-stage smoke checks pass.
- Use the official registration APIs and `RLINF_EXT_MODULE` for new methods where supported. Document and test any necessary upstream patch.
- Check launcher changes with `python -m unittest discover -s tests -v`; verify runtime changes with relevant real smoke checks.

- Container packaging uses the allowlisted snapshot in `bootstrap/build_recap_image.py` and `docker/`; keep model weights, training datasets, tokens and host GPU drivers outside images. A daemonless chroot smoke check is userland evidence; report Docker GPU validation separately.
