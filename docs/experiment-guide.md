# 实验分类与下一步任务

更新日期：2026-11-14。本文件解释实验编号和执行顺序；具体成绩、统计与解释保留在[实验结果汇总](previous-experiments.md)，两种服务器的详细职责见[两卡任务书](method-2gpu.md)与[八卡任务书](prerequisite-8gpu.md)。

我们研究的是：协调已有多任务VLA的SFT与RL后训练，缓解两个阶段的有害任务干扰，让SFT为后续多任务RL提供更易继续学习的初始化，并改善效率和能力保持。SFT→RL是当前研究主线，SFT-only／RL-only提供对照。当前从Motus多任务π0.5 checkpoint出发，不重新训练基础模型；模型与源码版本以[共同协议](multitask-critic.md)及[版本配置](../configs/multitask/phase0.json)为准。

policy／actor负责产生动作；critic负责估计回报；value head是critic的输出模块，完整critic还包括特征提取。adapter是加入主干前的可训练残差模块；action expert是原模型生成动作的网络。

SFT指模仿示范动作的监督训练。这里的warm-up指RL前的继续SFT／value准备训练，与学习率逐渐升高的warm-up不同。

当前value是给定图像、状态和instruction的标量回报预测；它不读取候选动作，不能直接称为“动作是否遵循instruction”的reward。学习instruction–action reward是待验证组件，目前仍使用终局二值奖励。policy本来就接收instruction，是否真正选对目标需要闭环检查。

## 研究目标与后续整体设计

研究对象是一个已经具备多任务能力的共享policy。用户明确选择研究SFT与RL的衔接：减少各阶段的有害任务干扰，使SFT既提供行为先验，又为后续多任务RL保留可学习性；在可比数据、交互和计算预算下改善更多任务并保留已有能力。需要区分SFT内任务间干扰、RL内任务间干扰，以及同时／交替训练时模仿与奖励目标之间的干扰。现有证据尚未证明这些机制都成立，不把它们合成一个已确认的冲突结论。

已有两任务证据覆盖接口、数据、critic、BC与policy更新的若干环节，但尚未建立共享critic瓶颈、instruction遗忘、联合更新额外退化或可靠的梯度干预收益。既有成绩统一见[实验汇总](previous-experiments.md)。两任务开发结果用于筛选机制，不能代替多任务、能力保持或最终测试结论。

| --- | --- | --- | --- |
| 1. 多任务后训练现象 | 哪些任务改善、哪些退化；是否超过继续SFT？ | 原Motus、成功BC、共享critic的公开RECAP流程基线；固定critic/更新方法的单任务与联合policy参考。两卡复用已有两个开发任务，八卡预先选4—6训练任务及未更新任务锚点 | 逐任务训练×评估矩阵、相对原SFT变化、最差任务和保持。单任务模型集合的总参数／总计算额外报告，不当作纯参数共享对照 |
| 2. 定位原因 | 数据／信号／policy使用分别在哪里失效？ | 固定actor比较真实／严格打乱／等量成功信号；固定信号做任务loss移除。审计过滤后曝光、真实动作时间、轨迹阶段、实际参数步及输出漂移 | 预测的中间变化需重复，再由闭环复核。已有单任务BC矩阵不等于固定RL标签下的loss移除实验 |

正式主比较至少包括原SFT、成功BC、标准RECAP基线和候选方法。原RLinf公开流程与本地native加权FM适配分别标明身份；候选方法还必须有同实现／同推理后端的普通更新参考，不能把后端或条件提示变化归给方法。原始RECAP回报定义单列；当前机制实验继续固定终局二值reward，无额外clock，不在同一轮同时更换reward、critic和policy更新。

### SFT到RL的交接与最小实验

数据按[母池与用途视图](multitask-critic.md#sft到rl的数据构建)构建：SFT成功示范、固定成败经验、按需的交接校准／在线训练经验，以及严格分离的开发／测试和未更新锚点。当前192条原Motus训练轨迹可派生首版每任务32条成功SFT视图，全部192条用于成败经验；尚未生成新视图。现有24场景仅开发用途，GRPO多rollout分组必须合格重采，不直接复用单次离线轨迹凑组。

此前将主线理解为在SFT与RL之间二选一不符合用户意图。当前直接研究更有效的SFT→RL：普通顺序流程是主基线，SFT-only与从原Motus直接RL只是判断阶段作用的参考。Motus本身已完成多任务SFT，这里的SFT指追加的受控多任务准备阶段，直接RL也不是从零训练。

主线不要求一定有critic：SFT准备的是策略和有效任务条件表征，随后可用于RECAP／PPO等价值引导更新，也可用于不学习value baseline的GRPO。critic准备只是前一分支的可选机制；若使用GRPO，应改测策略起点、组内相对reward信号、有效训练比例和后续学习曲线，不能继续以更低critic误差作为主要证据。GRPO仍需要reward、同任务／指令／受控初态的多次采样及正确的flow likelihood路径，不能由当前离线FM直接改名而来。

历史实验尚未证明“SFT让VLM本体特征更好并加速RL”：M2的原VLM和动作专家冻结，更新的是prefix adapter与head；后续部分实验增加动作专家更新，VLM仍固定。可讨论adapter后的有效表征，不能声称训练改变了VLM本体。有限选层只改善部分probe指标，W2也曾使actor退化，均不等于完整交接收益。如果未来要验证VLM本体适配，需要明确加入LoRA／解冻的真实训练对照，并与adapter-only分开，不自动改动现有冻结范围。

按用户最新空间管理要求，历史大DCP／优化器和非保留权重已清理，保留文件见`.runtime/storage/cleanup-report-v3.json`。旧结果仍可分析，但需要旧optimizer状态的交接／一步诊断必须在新目录重跑生成，不能假定原断点仍可用；原始模型、轨迹母池和小型W1／W2权重保留。

“更快warm-up”必须分别测量：SFT结束时actor能力、RL开始时critic准备程度、RL阶段学习速度，以及包含全部准备成本的端到端效率。起点成功率更高可以是实际收益，但不能单凭更早达到阈值就证明RL内在学习速度更快。若要归因RL可学习性，需同actor的critic配对，或在开发集预定检查点中寻找逐任务起始能力相近的对照，并在独立场景复核；只减去初始成功率不能排除起点差异。

| 组别 | SFT阶段 | RL阶段 | 要分开的作用 |
| --- | --- | --- | --- |
| A | 普通多任务SFT | 标准多任务RECAP | 普通SFT→RL完整基线 |
| B | 候选的任务协调SFT | 与A相同的标准RECAP | SFT阶段准备是否有独立作用 |
| C | 与A完全相同的SFT actor | 候选的任务协调RL | 固定起点时RL阶段协调是否有效 |
| D | 与B完全相同的SFT actor | 与C相同的任务协调RL | 两阶段协调是否互补，完整方法是否超过单阶段修改 |

四组是阶段归因设计，不表示候选SFT／RL机制已经实现或有效。A/C共用SFT末点，B/D共用另一个SFT末点；第一轮固定critic准备规则，隔离两阶段协调作用。若方法包含critic warm-up，另做同actor的提前准备（value stop-grad）与事后标准训练配对，匹配输入／容量／总预算。若让value梯度进入共享表征，再加匹配stop-grad消融，区分head初始化与actor表示变化。历史W0／W1已验证部分actor等价性，W2曾造成actor退化，优先复用已有证据，不能把W2直接当作有效方法重跑或包装。

“标准准备”不是把随机critic直接交给RL：所有组均按公开流程完成必要的critic拟合和优势生成。比较提前与事后准备时，固定价值数据来源、目标定义、总训练预算及handoff校准规则，分开记录阶段成本。SFT期间actor不断变化，而固定数据MC目标对应采集行为的后续回报；提前准备的head是初始化，不自动等于当前actor的准确value。若handoff新增轨迹用于校准，所有相关组按同一交互预算采集，并与纯离线结果分开。

只有成功示范、终局二值奖励且γ=1时，成功轨迹各决策的MC回报都为1，单独加value head无法得到有用的成功／失败排序。critic准备需使用可追溯的成功／失败经验或另有可靠监督，不能为方便拟合而随意增加dense reward。SFT动作监督继续使用可靠成功数据。暂不强制加入instruction–action reward或目标对比辅助。

1. **先封存完整交接基线与指标。** 核对A的普通SFT→标准RECAP流程、阶段预算和实际训练参数；从已有工件中复用完全匹配的部分，补固定预算点的RL学习曲线和逐任务保持。记录handoff前后、早期RL及最终的逐任务成绩；预先确定目标阈值／AUC口径、未达阈值的处理和critic校准规则。候选不能获得额外未计入的SFT、value或环境预算。
2. **分别验证SFT准备与RL协调，再验证组合。** 封存一个有明确预测指标的协调机制后，A/C使用完全相同的SFT actor和critic准备，B/D使用另一个共同actor和相同准备规则；不把初始化差异归给RL更新。critic warm-up按需另做同actor配对。普通SFT→RL、等成本更长普通SFT→RL、SFT-only、原Motus直接RL是简单参照。若两阶段持续使用BC监督，再加入固定BC混合系数／固定衰减日程控制，区分任务协调与额外成功重放收益。
3. **只针对可重复的干扰选择协调机制。** SFT阶段测逐任务学习进展、保持和监督分配；RL阶段测有效advantage／监督、任务保持和实际policy步。先检验按任务有界采样／loss权重、参考策略约束等可扩展简单控制；PCGrad只是既有诊断参考。提出跨阶段共享adapter、条件调节或更复杂路由时，需要同容量、相同可训练参数及实际任务响应对照；它们本身不是创新。144次独立任务loss移除检查继续作为按需有界诊断，不阻塞完整交接实验。
4. **八卡确认完整收益与扩展。** 仍未连接、仅规划；预先固定4—6个训练任务及未更新锚点，主比较至少3个actor种子，场景数按每任务50—100估算后依据精度和成本冻结。分别报告RL步数／GPU时、总SFT+critic+RL成本、训练任务收益与未更新技能保持。候选有稳定结果后再扩大任务与组合，不预先宣称解决50任务冲突。

RL先固定RECAP作为公开基线，避免同时改变SFT、critic和RL底座。当前native加权FM属于另行标明的研究适配。若主张减少环境交互，需要另立匹配交互预算的在线实验；固定离线D上的更少更新不能称为更少交互。GRPO不依赖学习的value baseline，不适合同时用来验证critic warm-up主张，先留作后续算法对照。

相关先例包括[ReFT](https://aclanthology.org/2024.acl-long.410/)的SFT warm-up→PPO、[PRISM](https://arxiv.org/abs/2601.07224v2)的SFT/RL数据分配，以及[SFT→RL可塑性交接](https://arxiv.org/abs/2606.09932v1)研究；这些语言模型结果不是本机VLA证据。仅SFT→RL、提前训练critic或加入BC项均不能单独作为创新，需要多任务VLA中的具体失效、匹配干预及效率／保持证据。

全部比较记录逐任务成功率及其变化、宏平均、最差任务、改善／退化任务数、未更新锚点保持、场景得失和成本。训练种子与评测场景两种不确定性分开；固定末点或预先规定的选择规则，不在测试集上选模型。已有24个反复使用的场景继续作为开发集，最终测试保持隔离；未用于本次后训练不等于Motus预训练未见。

## 当前主线：先确认现象，再验证原因

先放下未通过的I0／I1，以及尚未开展的语义reward、目标对比辅助、W3联合warm-up；它们不作为整体诊断的前置条件。A0／A1已经完成。当前证据支持“部分后训练设置会退化，真实critic标签的优势尚未建立”，尚未证明这是多任务特有问题。新计划先完成一轮基线诊断，再选择一个被证据支持的机制做干预与修复，不预设必须发现instruction遗忘或共享critic冲突。

| 顺序 | 要回答什么 | 最小对照与输出 | 何时进入下一项 |
| --- | --- | --- | --- |
| 1. 共同起点和数据 | 是否有可信的多任务能力及可比数据？ | 主线从锁定的原Motus SFT出发；W1作为已继续训练起点的单独参考，不混用。核对逐任务成功率、成功／失败来源、数据量、场景和实际采样曝光 | 复用已通过的接口／数据审计，只补新起点与新日程接口，不重复调层／损失 |
| 2. 单任务与联合更新 | 退化是否需要“另一个任务的训练”才出现？ | 固定成功BC先比较A-only、B-only、A+B；每个模型评A、B，形成更新任务×评估任务矩阵。critic不参与，先隔离共享actor训练现象 | 单任务也普遍下降：先查通用后训练／行为来源／更新强度；单任务可学习而联合额外下降：进入多任务机制定位；差异不明确则记为证据不足 |
| 3. 固定actor，隔离critic | 同等数据下共享critic是否比任务独立critic丢失有效信息？ | 同actor特征／输入、回报标尺、任务曝光；比较逐任务误差、校准、排序和advantage标签，记录独立模型总容量／计算。加入容量解释所需的参考 | 不要求critic拟合“过线”；结果无差别也继续报告完整基线，停止把共享critic当已证实瓶颈 |
| 4. 固定标签，隔离policy使用 | 标签语义、有效训练量、任务比例和共享actor更新各贡献多少？ | 主线在同一actor上比较共享／独立critic标签、严格打乱标签及成功BC；分别控制每任务有效曝光和更新强度。现有A1仅作该步骤的一次W1开发参考 | critic误差改善但标签或policy无变化，则链条在该处未成立；不能越过中间证据直接解释最终成功率 |
| 5. 最小机制干预和复核 | 所定位因素是否真的造成退化？ | 只修改一个因素，并加入能区分替代原因的匹配对照；检验预测的中间指标、受影响任务及闭环成功率是否同步恢复。固定预算复测训练种子与新场景 | 干预不能稳定改变中间环节或恢复结果，保留假设未成立；不为形成论文继续包装模块 |

因果链需要逐段验证：`固定数据／任务采样 → value误差与标尺 → advantage及实际动作监督分布 → 共享policy更新 → 逐任务闭环变化`。共享actor也可能直接受任务混合影响，因此先用无critic的步骤2分开这条路径。若单任务也退化，优先分析通用更新问题；若BC联合正常、critic标签更新才额外退化，才把定位重点转到RL信号。梯度负余弦、value loss和相关性只作辅助证据，不能独自证明因果。

## M2内部的方案：W0／W1／W2

三个方案都从相同已有SFT模型开始，动作SFT使用成功轨迹，value学习使用成功／失败轨迹。

| 方案 | 训练顺序 | value loss能更新共享adapter吗？ | 对照目的 |
| --- | --- | --- | --- |
| W0 | 先继续SFT，再冻结表征训练value head | 不能 | “先动作、后价值”的顺序参考 |
| W1 | SFT与value head同步训练 | 不能，adapter只接收SFT梯度 | 隔离value对共享表征的影响 |
| W2 | SFT与value head同步训练 | 能，adapter接收两种损失的梯度 | 检验共享价值监督的作用 |

原M2中VLM和动作专家均固定，共享可训练部分是adapter。在当前匹配日程下，W0／W1的actor实际完全一致；critic仍不同，因为W0读取最终固定表征，W1训练时表征持续变化。

## M4结果和日志里的名字

| 名字 | 含义 |
| --- | --- |
| W1 actor | 早期M4使用的W1训练后策略；当前新主线从原Motus开始 |
| C_W1／C1 | W1产生的完整critic快照，及其生成的固定优势标签 |
| C_W2／C2 | W2产生的完整critic快照，及其生成的固定优势标签 |
| BC | 只模仿成功轨迹动作，不使用critic标签 |
| weighted | 按固定优势标签构造0/1动作损失权重 |
| conditional | 为选中的正优势片段加入positive条件，其余普通输入；部署用positive |
| adapter_only | M4只更新adapter权重，critic固定 |
| expert_adapter | M4更新动作专家和adapter，VLM与critic固定 |
| coverage_small／large | 数据覆盖对照：每任务4／12条成功轨迹，均从W1做expert＋adapter的BC更新 |

最新的adapter-only参考为匹配数值路径，会计算但丢弃expert梯度，并将expert排除在优化器外；完整权重哈希已验证expert不变。判断更新范围看实际优化器和权重变化，不只看梯度开关。

例如：`expert_adapter-c2_weighted`表示在M4中，从W1 actor开始，用C_W2标签做加权动作学习，更新动作专家和adapter。C2表示评价来源，不表示策略从W2 actor开始。生成标签必须使用完整C_W2快照，不能直接把它的head接到W1特征上。

## 当前结论与证据范围

工程、数据、warm-up和多轮后训练诊断已完成，尚未证明共享critic瓶颈、VLM本体表征改善、联合额外退化或稳定PCGrad收益。早期多数对照只有一个actor种子，近期BC与梯度组有三个；head种子不能代替actor种子。最终测试、严格未更新任务保持和八卡正式实验均未完成。详细成绩只见[实验汇总](previous-experiments.md)。
