# 八卡5880：多任务基线与确认任务单

更新：2026-11-14。可直接转发给8×48GB机器执行端；当前未连接或验收远端，也未启动或发送远端作业。八卡负责正式数据、可信多任务现象、公开流程基线、候选确认及能力保持；与本机两卡方法开发并行。

从相同Motus多任务π0.5开始，固定RLinf `e1a82eb`、RoboTwin `dca9ec6`。完整来源、动作接口、数据与奖励边界见[共同协议](multitask-critic.md)。目标是SFT→RL协调，不是仅比较几个critic loss，也不重新训练基础模型。

执行端使用[RoboTwin 2.0总YAML／shell说明](sft-to-recap.md)，按八卡资源、正式任务和数据另建计划。默认两任务128步是开发预算，不能直接当八卡正式实验。

## 第一批可以直接安排的工作

| 顺序 | 实验／准备 | 交付与停止规则 |
| --- | --- | --- |
| 1. 环境与模型验收 | 校验锁定源码／补丁、Motus权重／norm、3相机与14维动作／32步chunk，核对推理、反向、导出／复载 | 原模型逐任务校准、显存和耗时；原生／CFG及新增条件提示做零更新核对，不把接口漂移当方法效果 |
| 2. 冻结正式多任务数据 | 首批4个训练任务，后扩4—6；另选2个未更新任务锚点。候选训练任务为瓶子、按铃、放空杯、放容器到盘，先按SFT能力与数据可审计性核验再锁定 | 任务／场景／初态、训练／开发／测试清单、示范／自主来源及hash。锚点须有可测原始能力，不按候选方法收益挑选 |
| 3. 建立完整后训练基线 | 原Motus、SFT-only、原Motus直接RECAP、普通追加SFT→RECAP；主要训练条件配对3个actor种子 | SFT末点、早期与最终RL逐任务曲线，原始能力保持和成本。主基线按公开官方流程，native适配另标身份 |
| 4. 分别测SFT和RL任务相互影响 | 各阶段从共同起点做任务单独／联合训练，并评估全部训练任务和锚点 | 训练任务×评估任务矩阵；同总预算与同每任务曝光分别比较。RL阶段的单／联合组固定相同SFT起点和critic／标签规则，不能混入初始化差异 |

先执行1—3即可形成正式基线；4可复用已封存的训练轨迹固定点，不通过验证结果选择有利组合。八卡不等待两卡提出方法才开始环境、数据和基线准备。全部N_SFT／N_value／N_RL与评测点在接口短测后、长训练前固定，开发128步不等于正式预算。

## 数据范围

- SFT使用可核验的成功示范；正式首版可按每任务32—50条预算，示范场景ID不足时不能认证严格split，先审计或采集可追溯经验。
- 固定行为池建议先按每任务128—200次预定尝试估算成本，全部结果保留，来源为同一原Motus。不是补采直到凑到某成功比例；覆盖不足报告缺口。
- 示范、value和RL可以引用同一训练母池；每个方法获得相同可用信息，额外失败标签、专家数据、交接采集和标注单列成本。
- 开发／最终测试按场景族拆分，最终既有seed列表索引`[500,550)`继续封存。已反复用于开发的场景不可改称测试；post-training隔离不等于Motus预训练未见。
- 未更新锚点不向SFT、critic、重放或正则提供数据；若使用了replay，就另列为rehearsal任务，并保留严格锚点。
- 主比较至少3个actor种子，按每任务50—100评测初态估算后依据精度／成本冻结；不能默认能分辨1个百分点差异。

现有两卡192条训练轨迹和24条开发轨迹可作为接口验收子集，不代替正式多任务数据；当前图像仅记录chunk边界，正式官方loader所需step级字段须核验，不能插值伪造。数据子集只建索引，跨机数据根路径可变、内容hash不变。

## 第二批：收到两卡候选后

候选须有明确机制、实现、配置和小规模证据；不直接启动未定义的“协调”方法。按相同阶段预算做：

| 组 | SFT阶段 | RL阶段 |
| --- | --- | --- |
| A | 普通 | 标准RECAP |
| B | 候选协调 | 与A相同的标准RECAP |
| C | 与A同一SFT末点 | 候选协调RL |
| D | 与B同一SFT末点 | 与C相同的协调RL |

先固定critic准备规则，配对3个actor种子、相同可用数据／参数容量／推理接口／停止规则。critic提前准备、value共享梯度、BC保持项等只做必要单因素消融，不展开所有模块组合。若涉及BC重放，保留固定混合／衰减参考；同时检查候选收益是否只是额外数据、计算或更高SFT起点。

稳定候选再扩大任务数和固定任务组合，报告未更新任务保持。4个任务的结果不称50任务收益；任务独立模型集合总参数／总成本更大，不能只凭其优势就宣称共享冲突。

## 指标与资源安排

每任务报告原SFT成功率、handoff成功率、RL固定点曲线、最终增益／退化、宏平均、最差任务、改善／退化任务数和锚点保持。记录每任务有效监督、真实动作时间、轨迹来源与阶段、额外critic成本和GPU时，训练种子与评测场景的不确定性分开。

“RL warm-up更快”同时按RL阶段预算和包含SFT／critic准备的端到端预算评估；原Motus直接RL少了额外SFT成本，不能只用相同RL步数就断言组合更省总资源。若主张更少交互，另立匹配交互预算的在线实验并计失败／过滤rollout；离线更新步数不是环境样本数。

先测单作业显存，再把8卡拆为多个种子／评测队列；例如实际确认每作业2卡时，可用3组训练＋1组评测，不默认每个实验独占8卡。当前本机native扩展只支持独立单卡NO_SHARD，不能直接套8卡分布式；正式多卡使用官方支持路径并验收。GRPO作为后续独立算法检验，先固定RECAP完成主比较。

## 本机已有证据与待解决问题

本机已完成工程／数据／数值、warm-up、标签、单／联合BC和梯度诊断，结果集中在[实验汇总](previous-experiments.md)。目前未建立共享critic瓶颈、联合额外退化或稳定PCGrad收益，不能把这些当作八卡实验的已知结论。Root下native仿真可用不等于所有参考planner可用，同场景多目标配对仍单独待验收，不阻塞普通任务基线。

历史大检查点已清理，不假定旧结果目录仍有可恢复DCP；保留源模型／数据／配置／结果。需要恢复的训练在新目录重跑，不恢复已取消优先级的LIBERO长预算。
