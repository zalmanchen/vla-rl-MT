# 固定离线数据下的多任务 Flow-VLA 后训练：诊断优先计划

> 本页保留研究分析，当前执行以[双线共同协议](../../docs/multitask-critic.md)为准。旧实验链接不再维护，实验事实集中见[摘要](../../docs/previous-experiments.md)。历史 LIBERO 优先级已由用户的新路线替代。

更新：2026-11-11（北京时间）。当前是研究计划；没有已确认的新方法或机理结论。

## 研究对象与边界

从同一个 Motus 多任务 SFT π0.5 checkpoint 出发，固定带任务指令的轨迹池 D，比较共享 action expert 的监督更新与 advantage-guided 后训练。数据组装阶段允许一次预先约定的自主采集，随后冻结 D；后续评估与诊断分支不回流训练。若增加数据或教师查询，另立预算分支。

先建立 RLinf 官方 RECAP 算法在 RoboTwin 上可运行的 baseline。算法、worker 和 runner 沿用固定官方版本；三相机、ALOHA 状态、动作窗口及模型统计的兼容补丁单独记录。普通 SFT 初始化、仅训练 action expert、短预算 pilot 都是对原论文设置的改变，须明确披露。

当前机器和运行状态以项目 README、`.runtime/bootstrap/recap-run.json` 为准；历史 E4/E7/E9 数字只提供待解释现象。E9 未经原始日志复核，不能作为新方法有效、critic 错误或共享干扰的证据。

## 可以证伪的主问题

在相同冻结数据、相同 advantage 标签和匹配预算下，新增条件的 flow 训练与无新增条件的加权 flow 训练是否存在可重复的性能差距？这个差距是否随任务共享扩大？

不预设差距存在，不预设 RL 优于成功 BC，不把一般条件生成策略的问题自动称作 flow matching 独有问题。

理想函数类下，给定同一二值标签，positive 条件生成与正例筛选的目标分布都是数据的 `D(a|context,I=1)`。两者的实际差别来自输入表示、有限容量、额外分支目标与优化，而不是筛选凭空获得更多行动质量信息。这一分布关系本身不是创新；冻结 VLM 接入不同 token 后也不能假设表示等价。

因此目前主问题可研究，但“multi-task flow RL 尚无人稳定改善”不是成立的空白表述；“目标对比改善 critic”也没有建立实质区别。若导师要求 flow 专属贡献，需要额外证明效应依赖迭代 velocity／时间条件等结构，并排除普通条件模型同样会有的问题。当前候选辅助 critic 本身没有这种专属性。

四组原因分别检验：

| 原因 | 识别所需干预 | 不能据以认定的现象 |
| --- | --- | --- |
| 条件接入／提取 | 固定标签比较条件式与加权 FM；相同成功动作上比较有无新增提示的 BC；检查训练过的分支 | 零更新 positive 有扰动、速度场不同 |
| 价值／标签 | 奖励与边界审计；独立行动排序诊断；同估计目标下的标签修正 | 终局分类好、MC/TD loss 小、改用成功标签后变好 |
| 覆盖／优化 | 有效样本曝光、更新曲线、已知可学对照；若 D 内有恢复数据，预先定义子集对照 | 所有学习器都没有提升 |
| 共享代价 | 基础单任务能改善后，匹配数据和主预算比较共享与独立策略 | 梯度余弦为负、共享模型下降 |

状态／历史不足也可能造成 critic 混淆；首先定义 critic 的参考策略、观察信息、奖励和剩余时域。当前官方 critic 的实际输入按源码审计，不假设 `include_state` 配置就代表本体状态已经进入网络。

本机源码还确认了两个独立的初始化差异：策略原来没有优势条件训练；critic 的 SigLIP→Gemma 投影（1152→640）、value expert 和 value 头也从随机初始化开始，只有视觉／文本骨干是预训练的。因此短预算退化不能只解释为任务语义或共享冲突。应先比较更多纯回报 warmup，以及冻结 π0.5 特征＋相同容量纯回报头，再判断目标辅助监督是否必要。

## 基础模型选择与改变顺序（2026-11-11 复核）

当前 Motus checkpoint 的模型卡明确是 RoboTwin 2.0 的 50 任务 π0.5 SFT，使用 Clean＋Randomized 数据、32 步预测窗口及 ALOHA delta-joint 变换，选型与当前环境相符：[模型卡](https://huggingface.co/motus-robotics/pi0.5_robotwin2)。这不能替代本机基础能力验收。

现有 0/4 是 CFG 实现的无条件分支；原生 RLinf 加载器只在一个观测上与其做过数值核验，尚无同场景原生／CFG 闭环对照。先在每任务 20—50 个预先固定的开发场景比较两条未更新路径，核对精度、三相机、状态／动作统计、正确场景指令及预测窗口与实际执行前缀；32 步预测窗口不自动规定必须开环执行全部 32 步。若短执行前缀作诊断，保持预测窗口与模型结构不变，并单独记账。

| 观测结果 | 下一步改变 |
| --- | --- |
| 原生路径可用，CFG 路径明显下降 | 修复或对齐推理接口，保持基础权重与数据不变。 |
| 两条路径均弱，示范 BC 能稳定改善 | 先在同一骨干上建立更可靠的 SFT 冷启动，所有后训练方法从该共同 checkpoint 出发。 |
| 对齐协议并补充 SFT 后仍不能学到基础任务 | 再比较另一个具备相同环境／机器人适配和可验证基础能力的多任务 checkpoint。 |
| 基础策略已可用，后训练仍下降 | 优先做条件接入、critic 与数据覆盖对照，不由此直接推断底座选错。 |

RLinf 的公开 RECAP 流程本身支持 π0.5；其 LIBERO-10 Task 0 示例采用 few-shot 初始化及 4,096 条自主轨迹：[官方文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/recap.html)。因此普通 π0.5 不是接口错误，但本机的普通多任务 SFT、小数据适配与论文 π*0.6 的优势条件预训练有差别，不能混称严格复现。

后续保留官方 critic 对照，先比较充分回报训练及冻结 π0.5 多模态表示＋纯 value 头；q／已知任务时限各作独立输入对照。条件适配用同示范上的普通输入 BC／positive 输入 BC，之后比较适配本身和适配＋RECAP。扩充数据时保存新的冻结数据池，各方法共用该池；当前 8 条自主训练轨迹只适合工程 pilot。以上均为待执行的对照，不是已证实的故障原因。

## 最小诊断顺序

1. 审计真实数据和运行路径：动作与图像对齐、频率、终止／任务时限、成功标签、源模型、训练／验证轨迹、参数更新范围、条件路由。实现错误先修复，并单独记录。
2. 零更新比较原始输入、positive、negative、两个中性提示。固定观测与动作噪声，在相同 `(x_tau, tau)` 上比较 velocity；独立生成轨迹之间的差异不能直接归因于条件。positive-only 训练没有已训练 negative 分支。
3. 做标签 × 提取方式的 2×2 对照：当前／独立诊断支持的修正二值标签，各自用于条件 FM／无新增条件的二值加权 FM（`w=I`，只保留同一批正例）。匹配正例曝光并报告总计算。连续 advantage 的指数加权另作强 baseline，不能在核心对照里同时改变条件接口和标签信息分辨率。加成功 BC 和关键单元的任务内标签打乱对照。轨迹结果粗标签不能自动称为更可靠 advantage。
4. 必要时在可恢复仿真状态上比较候选动作后的多次续跑，固定参考策略、估计不确定性。只用于诊断，不回流 D。若无法验证同情境行动质量，明确 H2 与 H3 尚不可识别。
5. 只有单任务更新有效后再比较共享。报告每任务数据曝光、总计算、每任务与总参数；这些预算通常不能同时完全匹配，不能把独立模型集合称为纯梯度冲突对照。

若不同标签仅在一种提取方式下有效，报告交互，不用顺序消融强行指定唯一原因。若普通 BC、任务均衡或 value warmup 解释收益，优先采用简单方案。

当前数据可立即支持的最小下一步是：先只用同一批示范正例，比较普通输入 FM 与固定 positive 提示 FM，保持采样、噪声、预算和可训练参数一致。这只检验条件接入，不需要先宣称 critic 标签正确，也不能解释失败数据的利用。现有官方配置可将 SFT 数据单独输入，并用 unconditional_prob=1／0 控制两种训练输入；闭环评估必须分别使用各自训练过的部署条件。评估入口已支持 `--trained-guidance positive`／`no_guide`，默认 positive；无条件 BC 必须选用 no_guide 部署。当前仅准备了该对照的运行接口，尚未执行这两组 BC 训练。

输入审计还包括：实例指令中的颜色、对象和手臂约束是否适用于当前场景；原生策略与 CFG 是否切换了计算实现／精度；不同数据来源是否仅凭指令就能被识别。当前本机的一个观测核验发现原生与 CFG 无条件动作存在小幅数值差异，因此新闭环对照全部使用同一 CFG 路径；这不解释历史 E9，也不是模型效果结论。

估计对象不能被语义直觉替代：同一目标的不同措辞可能改变参考策略行为，因此 `V^beta(s,l)` 不必对同义指令完全相同。若要求指令不变性，先说明是否固定了目标和参考策略。恢复仿真状态还需包含速度、接触、任务阶段标记、剩余时域及随机状态；相同 RGB 并不等于相同决策状态。

当前 pilot 的 HDF5 没有保存完整 SAPIEN 状态；种子与动作前缀能否精确复现中间状态仍需验证。两个任务的物体组成也不同，尚无经审核的同场景多目标标签。因此本数据池可以接通 baseline，暂不能支撑“反事实 goal 监督已解决 critic”或“oracle 标签仍无效”的结论。

### 进一步拆开条件输入与分支训练

由当前路由源码可直接推导：positive-only 模式把全部负例送入无条件分支，只把概率 p 的正例送入该分支。因此它并非在原始行为分布上训练无条件策略。若某上下文下原数据正比例为 rho，无条件分支中的正比例为 `p*rho / (p*rho + 1-rho)`；例如 rho=0.3、p=0.1 时约 4.1%。这是路由分布的性质，不是当前实验结果或创新。

因此训练后无条件分支下降可能部分来自训练目标本身，不能直接作为能力遗忘证据；能力保持应比较同一个部署条件下的逐任务表现。完整正负条件且对两类独立去条件，与 positive-only 路由也不是相同目标。

若条件 FM 不如二值筛选，先在同一批正例上比较普通 FM 与固定 positive 提示的 FM，识别新增输入的适配困难；再比较是否加入负例无条件分支，检查分支共享造成的优化影响。两者都不同于任务之间的共享干扰。若负例额外更新是原因，不能仅凭条件式／加权式结果差距声称模型未理解条件。控制正例曝光与总计算可能需要两组预算，不能声称一次比较同时完全匹配。

### 任务曝光与 chunk 参考策略还需要控制

即使原始采样任务权重相同，标签路由也会改变实际更新分配。任务 k 的采样质量为 m_k、正比例为 rho_k 时，positive 分支的更新质量正比于 m_k*rho_k，而非 m_k。按帧取样还使长失败轨迹占据更多预算。因此先报告任务×来源的总帧数、正例比例、positive／无条件分支预期曝光，再谈共享优化；任务均衡、标签分布和梯度处理不能在同一组对照里一起改变。这里是训练分布的直接分解，不是新算法。

自主策略一次生成并开环执行 32 步。数据中的中间帧后续动作还依赖此前已生成的 chunk；只给当前图像与指令的 value，估计的是这些历史及 chunk 阶段的混合。它不自动等于从当前观测重新规划的固定策略价值。若做同态续跑，先声明是续完原 chunk 还是立即重规划；保存／重放需包含 chunk 余量与决策阶段。示范和自主轨迹也不是同一个行为策略。改变该估计对象后变好，不能只归因为 critic 的任务语义改善。

本机官方 critic 日志的 `mae` 来自 argmax bin 到目标邻近 bin 的距离，不是用于优势的概率期望值 MAE；每批标准差的平均也不是整个数据集标准差，单样本批还会产生未定义 std。分析需用逐样本预测另算期望值误差、逐任务及逐 episode 排序，不能从这些聚合日志直接宣布 critic 已可靠。

| [Compounding Physical RSI](https://arxiv.org/html/2611.06654v1) | 阶段失败诊断、经验修复与保持的框架已有近邻；不能仅靠这一叙事组织创新。 |
| [VLA-MOPD](https://arxiv.org/html/2611.12286v1) | 已有教师合并、学生访问状态上的 flow-step 监督及参考保持；与本计划的固定数据、无教师设置不同。 |

| [Contrastive RL](https://arxiv.org/html/2206.07568v1) | 对比目标与 value 的联系依赖奖励及未来状态采样；任意 instruction 分类不自动满足这些条件。 |
| [FQL](https://proceedings.mlr.press/v267/park25f.html)／[DFQL](https://proceedings.mlr.press/v306/cao26f.html) | flow 的一步 Q 提取与各步 velocity 的 Q 引导均有工作；FQL 已补读算法与局限；DFQL 已补读方法、附录推导／局限与官方 actor 源码；其函数空间渐近解释不能当作共享网络参数更新的有限步保证，完整实证消融仍待核验。 |

补读 [ARFM](https://arxiv.org/html/2509.04063v1) 后确认其已有多任务加权 FM 和自适应温度，但奖励与训练预算不同；[RLT](https://arxiv.org/html/2604.23073v2) 是参考动作 chunk 的在线直接细化，含阶段交接等成本；二者仍有未核验消融。另补 [VLAC](https://arxiv.org/html/2509.15937v1) 的语义错配／进度辅助监督，以及 [MMBench/Newt](https://www.nicklashansen.com/NewtWM/newt.pdf) 的共享在线多任务设置，均不能直接替代本机固定离线预算下的对照。

### 本机 pilot 的早期 critic 核验

v2 在固定 500 步后的独立记录回报核验覆盖 4 条示范验证轨迹和 2 条自主失败验证轨迹（1,959 帧）。期望值 MAE 在示范按铃／叠块约为 0.054／0.055，在自主失败轨迹约为 0.112／0.199（均为 [-1,0] 尺度）；示范上的 modal-bin MAE 仅约 0.004／0.008。后者不能代表用于优势的期望值已同样准确。两条自主失败轨迹内与记录 MC return 的 Spearman 为负，但每任务仅一条，且失败 MC return 本身受剩余时限支配，不能据此宣称真实动作排序或任务语义错误。

这是 checkpoint 接通后的有限诊断，未用于选择当前 checkpoint，也不作为策略收益证据；原始预测与图在 `.runtime/runs/recap-pilot-v2-20261111/critic-validation.*`。目前更支持先做纯回报 warmup／表示和分布预测基线，而不是跳过诊断直接加入 goal 辅助项。

优势标注后，4,230 个自主训练帧中 1,069 个被标为正；8 条自主轨迹各自最后 32 帧全部为正，其中包含 6 条失败轨迹的 192 帧。失败轨迹也可能含好动作，因此该计数不是标签错误的真值。需要优先检查一个更简单的解释：有限时限和每步 -1 使失败 MC return 随剩余时间变化，而当前 critic 没有时钟；近似不变的停滞画面可能对应不同剩余回报，终止 bootstrap 又被置零。它可能产生边界偏差，但尚未做干预证明。

按 [Time Limits in RL](https://proceedings.mlr.press/v80/pardo18a.html) 区分固有 deadline 和外部截断，再比较同容量纯回报 critic 有无可知的 elapsed time／任务硬时限。不能使用“该记录距最后一帧还有多久”作为输入，那会在成功轨迹上泄漏未来。即使加入时钟减少回报误差，也必须继续验证行动排序与独立策略效果；该修正是已知建模基线，没有新颖性主张。 追加的训练集拟合、验证集评估的线性控制并未带来一致改善：V＋elapsed time 使自主叠块 MAE 从约 0.199 降至 0.168，却使自主按铃从 0.112 升至 0.134；仅时间基线更差。它不是端到端时间条件 critic 的实验，既不能证明时钟是主因，也不能否定该建模问题；记录在同目录的 `critic-time-controls.json`。

### 完整 pilot 的开发结果

固定 500 步 critic＋500 步策略后，12 条配对回合全部执行完成：基础无条件 0/4、零更新 positive 2/4、训练后 positive 1/4。该小样本没有显示后训练收益，也不支持“新增 positive 提示必然有害”的普遍判断。它不能区分 H1—H4；应按前述最小条件接入对照、critic warmup／输入检查推进，而非由一次下降直接推出共享梯度冲突或目标对比方法。

四阶段、真实参数更新、复载、奖励与优势边界已审计通过；这是工程证据，保存在该运行的 `readiness.json`。额外的 500→502 恢复测试仅检查执行接口，没有用于选择或评价原来的 500 步策略。

## 有条件的最小方法

目前不确定核心方法。只有诊断同时支持“任务相关表征导致 critic 行动排序错误”以及“提取器能够利用更好的标签”时，才尝试辅助监督 critic。

冻结 `z=f_SFT(o,l)`，训练共享映射 `h=g_phi(z,q)`，其后接 value 头与完成判断头。以原始目标的轨迹回报训练 value，以可验证的状态—目标完成标签训练辅助头：`L = L_return + lambda * L_completion`。两个独立头若只读取冻结特征，没有共享可训练路径，辅助损失不会改善 value。

完成标签不是新 reward、任意 Q 或动作 advantage。允许多目标同时成立；未知标签忽略。替换目标后不能照搬原轨迹回报，当前未完成也不意味着不可达。冻结 critic 后，保持相同优势构造与条件路径更新 action expert，不叠加新采集、奖励学习或额外策略头。

必要对照：相同特征、容量和计算的 lambda=0 value；普通 value warmup；辅助标签打乱；成功 BC；同标签的加权 FM。若声称语言理解，再比较 task-ID 条件。检查辅助标签是否仅识别物体／背景，而非同场景目标差异。

从官方小 VLM 改为冻结 π0.5 特征会同时改变骨干及预训练跨模态对齐，必须先报告纯回报版本，再加入辅助项。否则无法将收益归给目标对比。

必须依次通过完成判断、同情境行动排序、独立闭环改善三个层次。只提高分类准确率就停止方法主张。冻结大模型特征也有提取和缓存成本，不能预设其比小 VLM critic 更高效。

该候选目前是辅助监督 baseline，不是已建立 novelty 的方法。

## 预算、评估与继续／转向条件

数据按完整 episode 和源场景分组划分；训练、critic 验证、方法选择、最终确认分别记录。已有 E9 场景保留为开发集。最终测试不参与阈值、采样、checkpoint 或机制选择。

先用一个训练种子排错，再对关键比较补到至少三个种子；按场景配对并考虑训练种子层级的不确定性。每任务 100 场景是起点，不能承诺识别几个百分点的差异。报告逐任务增益、保留／丢失／新增及未参与后训练任务的能力保持。后者不自动称为真正未见任务泛化。

分别报告轨迹、人工／仿真标注、特征提取、critic、actor、额外教师与评估成本。固定数据与新增交互的结果分开；教师合并与直接共同后训练分开。经典多任务 RL 的结果不直接替代现代 flow-VLA 证据。

本机首次配对开发验收中，无条件基础策略每回合墙钟均值约为按铃 27 秒、叠积木 37 秒（各 2 条，均到时限）。两任务×100 场景×3 训练种子×4 方法是 2,400 条评估；按该测量仅作规模示例，约 21 小时串行。成败长度、条件路径、模型加载与并行资源会改变耗时。先排错再扩量，不能把 12 条工程验收当作统计结论。两任务 pilot 也不能直接支撑任务规模扩展或 50 任务能力保持的主张。 进一步扩展前固定“任务”的定义：目标／技能、物体和场景是不同轴，随机种子不自动增加技能数；物体多样性与场景多样性应分别控制。

若条件路径主导，聚焦 SFT 条件适配；若数据覆盖主导，明确固定数据边界，再设计另一个允许新增经验的研究分支；若共享与独立策略相当，放弃冲突动机。若没有稳定效应，保留实现与负结果，不为了论文增加复杂组件。
